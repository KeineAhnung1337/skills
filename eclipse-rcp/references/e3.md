# e3 workbench / compatibility layer

Look for `org.eclipse.ui` and workbench extension declarations in `plugin.xml`, `org.eclipse.ui.application`, `ViewPart`, `EditorPart`, `IWorkbenchWindow`, perspective factories, commands/handlers, activities, and selection services. An e3-style RCP can run on the modern e4 workbench via its compatibility layer; it does not follow that its parts may be replaced by native e4 parts without revisiting the product model and extensions.

For performance, inspect costly `ViewPart.createPartControl` / editor creation, eager view instantiation, selection-change handlers, decorators, content providers, and resource change listeners. Narrow listener scope; unregister in `dispose()`; avoid doing I/O, workspace scans, or expensive model computation in UI callbacks. Use jobs and coalesced refreshes for background data, and marshal *only the UI update* to the display. Do not touch a disposed control after asynchronous work completes.

When updating a JFace viewer: separate content/model computation from SWT access, prefer incremental/delta updates to reloading enormous trees, and consider `SWT.VIRTUAL` only when its viewer/content-provider contracts are met. Measure allocation and UI time; virtual mode is not a universal fix. Preserve workbench selection, command enablement, persistence and editor dirty state.

Read local guide `guide/workbench.htm`, `guide/workbench_jobs.htm`, `guide/workbench_scalability.htm`, `guide/workbench_basicext_views.htm` and corresponding `reference/api/org/eclipse/ui/` Javadocs. Check `reference/extension-points/` for the exact extension declarations your product uses.
